## 2. 首版范围与优先级

### 2.1 必须交付

- 独立 Vue 3 + TypeScript + Vite 工程，电脑浏览器优先，手机核心操作可用。
- 固定路明非，按已审定剧情进行章节推进、条件选择、有界自由输入及结局处理。
- 每次选择后显示新的一页：“上一选择结果 + 自动承接正文 + 下一场正文”，配合新选项。旧页保存在只读剧情记录；主阅读区不无限追加历次正文。两区保持同页 70% / 30% 固定分区、独立滚动，不在段落间插入“继续”按钮。
- 自动保存、检查点回退、存档导出及导入。
- 正常游戏与章节测试隔离；测试支持指定已实装章节、返回目录、重开本章。
- 字号调整、明暗主题，首版采用简洁可用的阅读界面。
- 第一季完成记录和季终存档保留。

### 2.2 后续范围

- 正式 UI 风格、成套美术、立绘、剧情插画、配音和音乐制作。
- AI 互动、第二季及第三季、其他角色的可玩内容与解锁规则。
- 云存档、账号及自动跨设备同步。

首版按需要提供真实可用的功能入口。尚未实现的图片、音乐或 AI 功能不以无效按钮占据阅读页面。用户所说的“八九成玩家满意”是后续体验目标，需有实际反馈才能评估，不作为已经达到的结果。

## 4. 程序结构

建议将可运行工程放在 `05-游戏程序/`，与原始剧情材料分开。全部运行依赖位于本项目内；运行时不读取《龙族大世界》的目录。

| 部分 | 职责 | 不负责的事项 |
| --- | --- | --- |
| `src/content/` | 运行剧情包、章节目录及测试前情的选择路线 | 页面样式、直接写浏览器存档 |
| `src/engine/` | 选项过滤、输入匹配、状态变化、节点推进、检查点及结局判定 | Vue、浏览器 DOM、背景与音乐 |
| `src/session/` | 将引擎结果与存档、界面状态连接；区分正常游戏和测试 | 改写权威剧情规则 |
| `src/storage/` | 浏览器保存、读取、导入导出和版本验证 | 根据界面显示猜测剧情状态 |
| `src/components/` | 阅读区、选项区、输入区及必要功能面板 | 直接修改旗标或自行判断结局 |
| `src/styles/` | 布局、字号、主题、间距及可替换的视觉样式 | 改变剧情路径 |

组件、状态连接和函数按实际规模实现。首版页面可通过简单视图状态切换，不因旧工程使用 Router 或 Pinia 就自动引入同样依赖。

## 5. 剧情执行顺序

一次玩家操作按以下顺序完成：

1. 检查操作对应的节点仍是当前节点，并从当前状态计算可用选项；过时页面或重复操作不能再次结算。
2. 输入操作先执行有界匹配；按钮操作使用明确的选项 ID。
3. 选择成立后写入该选项效果。
4. 按原数组顺序判断后继规则，使用首个全部条件满足的结果，否则取默认后继。
5. 进入节点时应用入口效果一次，再追加该节点实际正文。
6. 节点为有效检查点时，记录可恢复快照；结局与检查点按第 8 节分别处理。
7. 无需玩家选择时，继续计算自动后继并追加正文；到达真实选择或结局时停止。
8. 保存这次操作形成的完整状态，再向界面呈现对应结果与保存状态。

多个条件需同时满足；缺失旗标视为 false；条件未写期待值时期待 true。自动路径遇到无效引用、无法推进或状态不变的循环时，报告对应节点错误并保留上次有效状态，不跳过剧情继续执行。

已保存状态恢复时不重新执行已经发生的入口效果。恢复内部检查点时，记录其所处执行阶段，避免重复追加检查点正文或重复结算。

### 有界自由输入

- 仅当前可用选项参与匹配；完整按钮标签优先精确匹配。
- 根词按对应参考稿对齐，不统一改写成不同版本的规则，不通过大量添加同义词扩充玩法。
- 唯一命中时执行对应预写结果；多个不同意图时提示玩家明确选择。
- 未匹配时保留输入及当前剧情状态，提示重述或选择现有选项；不作任意猜测。
- 不显示隐藏选项的正文或关键词。

### 6.2 最小页面结构

- 顶部：游戏及章节标题、保存状态、菜单入口；测试会话明确显示测试标识。
- 顶部栏下方为一个占满可用高度的主内容区域，按上下 70% / 30% 固定分配正文与行动区。比例以扣除顶部栏等固定占用后的可用主内容高度为基准；窗口尺寸变化时重新分配，选项数量变化时不改变分区。
- 上方 70% 为正文阅读区：这里仅显示当前合并页：上一选项的结果、沿途自动承接正文及下一场正文。章节名只显示在顶部栏，不在正文或剧情记录正文中插入章节标题，以免打断衔接。正文过长只增加本区内部的滚动长度，不撑高整页。
- 下方 30% 为行动区：始终位于主内容区域底部，显示当前可用选项及有界输入。它有自己的布局空间，不覆盖正文。
- 菜单：只读剧情记录、检查点、导出存档、导入存档、阅读设置、返回入口。
- 入口页：开始游戏、继续已有进度、章节测试。
- 结局及阶段试玩结束时，正文区显示对应内容，行动区显示回到检查点或返回入口等有效操作，继续保持分区；季终完成另行保存。

界面关系示意（非正式视觉稿，比例以文字标注为准）：

```text
┌────────────────────────────────────┐
│ 章节标题、保存状态、菜单             │
├────────────────────────────────────┤
│ 正文阅读区：主内容高度的 70%         │
│                                    │
│ 本页选择结果、承接正文及下一场正文     │
│ 内容超长时，仅本区上下滚动           │
│                                    │
├────────────────────────────────────┤
│ 行动区：主内容高度的 30%             │
│ 当前选项；装不下时在本区内部滚动     │
│ 有界输入及反馈也安排在本区内         │
└────────────────────────────────────┘
```

**固定高度与滚动规则：**

1. 正文与行动区是同页的两个独立容器。长正文或大量选项都不产生带动两个分区一起移动的主页面滚动。
2. 行动区无论出现零个、一个或多个选项，都保留下方 30% 的空间；不通过自动收缩、按内容撑高或临时隐藏整个区域改变正文高度。自动转场期间也不增加“继续”按钮。
3. 新节点可操作时，行动区从选项列表顶部展示，让玩家第一眼看见可执行选项。选项多或文字长时，全部选项都可通过该区内部滚动到达，不裁掉内容，也不靠缩小字号硬塞。
4. 滚动正文不改变行动区的滚动位置；滚动行动区不改变正文的滚动位置。一个区域滚到边界后，鼠标滚轮或触摸滚动也不继续带动另一区域或整页。
5. 有界输入、提交及输入反馈在下方 30% 内排布，输入框增长或提示换行不能扩大行动区。优先保持选项可见；选项列表拥有可滚动空间，必要的输入控件保留在区内。
6. 上一选择作为本页结果的提示，旧页放入只读剧情记录，不能重新点击执行；当前可操作选项统一位于行动区，避免上下重复。
7. 玩家完成选择后一次性切换到新的合并页，正文滚动回到页首，先读到选择结果，再读到下一场正文。当前页内可自由滚动；旧页通过“剧情记录”只读翻阅，关闭回看后返回当前页及原滚动位置，不改变选项或剧情状态。
8. 手机继续采用同样的固定比例分区，不退回整页滚动。输入键盘出现、屏幕旋转或字号变大时检查两个区域的可操作性；分区按实际可用高度调整，不能由选项内容决定高度。

### 6.3 页面读取的数据

| 页面所需数据 | 含义 |
| --- | --- |
| 当前章节 | 显示用名称与标题，按显式章节目录取得 |
| 阅读记录 | 按真实选择划分的完整合并页面，含当时实际展示正文及已选行为，保留稳定记录 ID；从既有历史可重建页边界 |
| 当前可用选项 | 当前节点标识、选项 ID 和可见标签，不含隐藏条件或原始旗标 |
| 输入反馈 | 未匹配或歧义时的简短提示 |
| 可用检查点 | 已到达且可恢复的检查点 ID 与显示名称 |
| 会话状态 | 正式或测试、等待选择或结束、保存状态 |
| 结局信息 | 已抵达结局的显示内容及是否完成第一季 |

界面接收只读显示数据，通过明确动作提交操作：选择、提交输入、恢复检查点、开始或继续游戏、进入或重开章节测试、导入导出、修改阅读设置。选择与输入携带当前节点 ID，避免旧界面的迟到操作作用到新节点。

这些动作由会话层调用剧情和存档模块；页面不能通过直接更改显示数据改写剧情。Vue 使用有类型的组件输入与事件，接口名称和具体类型将在开发计划中落实。组件输入遵循 Vue 的单向数据流约定，见 [Vue Props 官方文档](https://vuejs.org/guide/components/props.html)。

### 6.4 阅读设置及后续扩展

- 首版字号提供小、标准、大三档，初始建议 16、18、20px；默认 18px。阅读容器响应屏幕宽度，行距先取约 1.8，并在阶段试玩检查中文正文实际效果。
- 首版提供明暗主题，默认明亮主题；两套颜色集中定义，阅读设置单独保存。
- 键盘可以到达选项及功能入口；手机按钮便于触按，放大文字后不出现横向溢出或遮挡。
- 字号变化只影响区域内部文本排版；正文区与行动区继续保持 70% / 30%，内容超出时使用各自滚动。键盘焦点进入未显示选项时，仅在行动区内将其滚动到可见位置。
- 主题、字号、间距和阅读宽度集中管理，后续正式设计主要修改样式和显示组件。
- 未来背景图可通过独立资源映射关联场景或节点，音乐可由独立播放组件响应场景变化；当前不增加未使用的资源字段、播放代码或联网接口。
- 未来新增会影响玩法的功能仍需明确剧情规则；“UI 接口可扩展”不意味着可以绕过剧情审核直接增加状态。

## 7. 存档与检查点

### 7.1 建议的数据组织

剧情存档建议使用 IndexedDB；字号与主题使用小型本地设置记录。IndexedDB 支持浏览器端结构化数据与事务，适合保存阅读记录和检查点，见 [MDN IndexedDB 文档](https://developer.mozilla.org/en-US/docs/Web/API/IndexedDB_API)。浏览器保存和读取集中在存储模块，界面与剧情引擎不直接调用存储 API。

首版保留一个当前正式周目，以及各个已经达到的季终结局最近一次归档。不同分支可通过检查点重玩，或导出当前周目保存；不在首版增加多槽位管理界面。

正式会话保存：格式版本、内容版本、固定角色、当前章节与节点、执行阶段、旗标、已展示的阅读记录、选择历史、已到达检查点及时间信息。

每个检查点保存：剧情位置、执行阶段、当时旗标、阅读记录截断位置和选择历史截断位置。检查点不重复保存整份阅读历史。

回退时恢复快照并截断后续阅读记录、选择及该路线后续检查点。重新走出的路线生成新的结果；已经单独归档的季终存档保留。

### 7.2 保存与导入导出

- 在新游戏到达首个选择、每次有效操作完成连续推进、检查点回退完成及抵达结局时保存。
- 恢复后保持实际展示过的条件正文，不用当前旗标重新拼出另一份历史。
- 导出文件包含格式与内容版本、当前正式会话和已归档季终存档；阅读偏好不影响剧情恢复。
- 导入先检查项目标识、版本、节点、选项记录、旗标类型及状态一致性，验证通过后一次替换正式保存；测试状态不能导入为正式通关。
- 覆盖已有进度前提示用户确认。导入失败保留现有保存。
- 首版只接受受支持内容版本，不承诺兼容旧游戏存档；后续内容更新若需迁移，单独制定迁移规则，原文件仍可留存。
- 保存失败时显示未保存状态及重试入口，不能显示“已保存”；导出功能允许玩家保全当前有效状态。

## 8. 第一季结束后的行为

- 前期临时结局只结束当前路线，不记录第一季完成，也不继续进入被该结局终止的主线。
- 第十二章根据参考稿判定季终结果，第十三章读取该结果完成收束。结局旗标在允许写入的阶段保持互斥；普通前期存档不要求已有结局旗标。
- 在正式游戏的第一季结束节点记录完成状态，并保留对应季终完整存档。
- 结局节点不覆盖上一个适合回退的剧情检查点；季终归档与可重玩的检查点分别保存。
- 玩家可返回入口或回到已到达的检查点重玩。已抵达的季终归档可通过入口载入查看，但不显示未抵达结局的剧透内容。
- 第一季完成不会自动开放其他角色、第二季或三季通关奖励。
- 测试会话可以查看结局，但不产生正式完成记录或角色解锁。

## 10. 验收要求

### 10.1 程序与内容检查

1. 逐项核对运行内容与对应参考稿，保留差异和修正记录。当前尚未开展全文对齐，不能宣称已经完成。
2. 节点标识唯一；章节入口、选项目标、条件后继和结局引用有效；无意外断路或无法结束的自动推进。
3. 依据参考稿验证前期临时结局及三个季终结局的合法路线，不能通过直接设置结局旗标代替验证。
4. 条件选项验证满足与不满足两侧；关键前置条件验证缺失时不能错误开放结果。跨章准备、线索和回响具有对应验证记录。
5. 验证完整选项标签、根词、自然短句、多意图歧义、宽词不匹配以及条件关闭，按对应参考稿的适用规则执行。
6. 选择效果先于后继判断，入口效果在正文展示前发生且只发生一次。回退和恢复不重复结算。
7. 正常退出再恢复、检查点回退、导出再导入，均保持剧情位置、旗标和实际阅读历史一致。
8. 章节测试默认路线可实际走通，且不改写正式进度、季终归档或解锁记录。
9. 验证首次生命交易只结算一次、季终结果互斥、第十三章不重新判定结局等参考稿明确约束。

### 10.2 叙事与实际体验

- 结合原著和参考稿核对人物知情范围、事件顺序、物件来源、选择动机及结果回应；原稿疑点由用户裁定。
- 正文不泄露后台旗标或未到揭示时点的信息，不出现审阅标记。
- 在电脑浏览器完成阶段试玩及第一季代表路线的实际操作检查，在手机视口检查阅读、选择、设置、回退及导入导出。
- 每次选择后从页首显示“上一选择结果 + 下一场正文”，自动承接段均包含在同一页，底部直接显示下一组选项；无“继续”按钮。旧页只读回看不改变状态，关闭记录后保留当前页位置；字号和主题不改变剧情。
- **固定分区验收：** 在同一可用窗口高度下切换不同正文长度、零个/一个/多个选项及长选项，正文区与行动区始终保持 70% / 30%；行动区边界和高度不随节点内容跳动。
- **选项可见验收：** 使用超长正文进入选择节点，无需先把正文滚到底即可看见行动区及首个可用选项；超量选项均可在行动区内部滚动到达，不能被裁切。
- **独立滚动验收：** 分别使用鼠标滚轮、触摸和键盘操作两区，验证各自位置独立；达到滚动边界后也不串动另一区域或整页。剧情记录单独滚动；打开、翻页及关闭记录不移动当前正文或行动区。
- **移动与设置验收：** 在手机视口、横竖屏、大字号及输入键盘出现时检查固定分区、输入及选项的可达性；文字换行不把行动区撑高，不遮住正文或必要操作。
- 用户进行最终剧情与阅读体验验收。已发现的剧情错误、分支规则错误及阻断游玩的问题修复并复验后，才算正式通过；视觉美化另行迭代。

自动检查、浏览器操作检查和用户体验验收分别记录，不能用静态图可达、旧工程测试通过或历史清单已勾选替代新程序验证。验证覆盖已定义的规则、关键分支和合法路线，不声称穷尽全部选择组合或证明绝对无错。

## 11. 实施顺序与交付
